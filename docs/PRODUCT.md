# Rphotos: требования и этапы

## Согласованный продукт

- База: ViewSkater / egui. Не новая оболочка на другом UI-фреймворке без
  отдельного решения о переносе ядра.
- Linux — основной, Windows и macOS — целевые платформы.
- Референс: Photos 2019.19041.20110.0, но не ресурсы или брендинг Microsoft.
- Разделы: Коллекция, Альбомы, Папки, Избранное. Группы по датам, шкала времени,
  три плотности миниатюр, выбор нескольких снимков, ручные альбомы.
- Мышь, клавиатура, тачпад и сенсорный экран равноправны. Горизонтальный свайп
  между разделами, вертикальная прокрутка с инерцией, pinch-to-zoom и pan;
  горячие клавиши и доступные подписи элементов.
- RU/EN с переключением в настройках. Светлая, тёмная и системная темы.
- Верхняя шапка с настоящим размытием фона за окном и непрозрачным текстом.
  Платформенная реализация, честный fallback при отсутствии поддержки.
- Системные печать и «Поделиться»; на Linux доступность конкретных механизмов
  проверяется по окружению. Не выдавать «Открыть с помощью» за системный share.
- Локальные поиск по имени/пути/метаданным, OCR и смысловой поиск RU/EN.
  Модель выбирается по лицензии, качеству, размеру и CPU-производительности.
  GPU необязателен. Скачивание моделей требует согласия, офлайн-просмотр
  не должен зависеть от них. Анализ фотографий не отправляется в облако.
- Автоматические альбомы по событиям/датам/содержимому; сохраняемые запросы.
- MCP — необязательная, по умолчанию отключённая интеграция. Направление
  (клиент, сервер или оба) пока не выбрано пользователем. Раздельный доступ
  к индексу, миниатюрам, оригиналам и изменениям; никаких автоматических
  разрешений на всю библиотеку.
- Поворот/отражение JPEG/PNG, Undo и resize добавлены отдельно. Полный редактор
  с обрезкой/коррекциями остаётся отложенным.
- Исключены видео, OneDrive/облако Microsoft, People/распознавание лиц,
  Windows Insider и импорт с USB/камер.
- Публикация под именем Rphotos на GitHub пользователя. Не публиковать
  личные фото, снимки экрана планшета, абсолютные личные пути и SSH-данные.

## Архитектурные границы

Существующие `decode`, `cache`, `pane`, `file_io`, RAW-preview и анимации
сохраняются как база просмотра. Они зависят от egui, не являются отдельной
готовой библиотекой. Новые сцены библиотеки не должны блокироваться декодером.

Добавлены: библиотечный индекс (SQLite, версия схемы), фоновое сканирование
источников, дисковый кеш миниатюр, модель ручных альбомов, виртуализированная сетка.
Добавлены базовые арбитраж жестов, очередь локальных OCR/descriptions и Linux
адаптеры системных возможностей; это ещё не полная приёмка этих функций.
В UI не должно быть обещаний работающей функции, если backend отсутствует.

Индексация: фон, пауза, отмена, лимиты нагрузки и повтор после сбоя. Чтение
фотографий не меняет оригиналы. Возврат из просмотрщика сохраняет раздел,
позицию прокрутки, фильтр и выбор. Удаление только через корзину с подтверждением.

Fit-текстура по-прежнему ограничена8192, но native100% больших файлов использует
фоновые viewport tiles2048px без уменьшения. Worker удерживает один полный decode,
это не disk-backed/out-of-core decoder. Embedded RGB ICC преобразуется LittleCMS
в sRGB; monitor ICC/CMYK/16-bit end-to-end workflow ещё не реализован. RAW сначала
использует embedded JPEG, при его отсутствии пробует установленный LibRaw.
Полное качество камер/мониторов требует реальной приёмки, не только synthetic tests.

## Порядок разработки

1. **Основа:** происхождение/лицензии, независимые имя и настройки, сборка Linux.
2. **Проверка рисков:** региональное compositor blur на KDE Wayland, адаптеры
   Windows/macOS; touch-поток egui/winit, pinch/pan/swipe и захват жестов.
3. **Первый рабочий сценарий:** источник → фоновый индекс/миниатюры → Коллекция
   по датам → просмотр через существующий кеш → возврат на прежнее место.
4. **Библиотека:** Папки, ручные альбомы, выделение, таймлайн, плотность сетки,
   локализация, темы, сохранение состояния и горячие клавиши.
5. **Интеграции:** системные печать/share, обработка отсутствующих backend-ов.
6. **Локальный анализ:** OCR, смысловой поиск RU/EN, автоальбомы и квоты индекса.
7. **MCP и релиз:** уточнить направление, разрешения, сборки трёх ОС,
   авторизованный GitHub, собственные иконки и проверка лицензий зависимостей.

Критерии проверяются реальными действиями и тестами; статический макет не
подтверждает производительность, поддержку жестов или системное размытие.

## Срез реализации

Основа и первый сценарий реализованы; из этапа библиотеки работают источники,
ручные альбомы, выделение, поиск по имени/пути/локальному тексту, плотности сетки,
таймлайн/выбор месяца, RU/EN и темы. Состояние сцены, индекс, альбомы, избранное,
пропорции миниатюр и настройки переживают перезапуск. Добавлены плитки каталогов,
полностраничные Settings, карточки альбомов и подсказки поиска.

Одиночный просмотр получил Photos-подобную сцену с RU/EN, темами, командной
панелью, боковыми зонами перехода, масштабом по кнопке, сведениями слева,
слайд-шоу и подтверждением корзины. Режим сравнения оставлен расширенным.
Базовые свайп фото/pan/pinch обрабатываются; реальное устройство ещё не принято.

Есть Wayland EXT/KDE blur, native Windows/macOS adapters, aspect-aware строки,
дисковая квота thumbnail-кеша16GiB (0=unlimited, GPU soft512MiB),
пауза/отмена, Print portal/PDF, file clipboard, локальные OCR/descriptions и
автоальбомы по датам и сходству текстовых embeddings. Отдельный opt-in смысловой
поиск использует локальный Ollama и уже установленные модели, без download.
Отмена сканирования кооперативная, незавершённый источник
не теряет прежний индекс. Оригиналы не меняются при работе с индексом/альбомами.

CI ранее успешно собирал три OS; новые native adapters требуют повторной сборки
и нативной приёмки. Не закрыты: приёмка blur/touch/print/share,
локализация расширенного сравнения, EXIF container coverage, приёмка watcher,
приёмка смыслового поиска/тематических автоальбомов на реальной модели, точный picker/переходы
референса и релиз. Реальные Tesseract/Ollama на машине не установлены;
проверены mock-адаптеры, не качество анализа. MCP остаётся невыбранной опцией.
