# Photos 2019: подробный интерактивный аудит

Дата: 2026-10-18. Референс: Microsoft Photos **2019.19041.20110.0**,
Windows 10 LTSC, экран 3000×2000, масштаб 200%.

Цель — воспроизведение композиции, размеров, состояний и переходов, а не
«похожий просмотрщик». **Текущий Rphotos существенно расходится с референсом.**
Этот документ не является отчётом о готовности Rphotos.

## Доказательства и пределы проверки

- Использованы реальные нажатия мышью/клавиатурой, UI Automation с координатами,
  выбранными значениями и поддерживаемыми patterns, снимки экрана.
- Сырые материалы хранятся локально вне репозитория в
  `/tmp/opencode/rphotos-audit`: 119 деревьев UI и 75 пар PNG/preview на момент
  окончания сеанса. Это рабочий журнал, не эталонная публичная тестовая выборка.
- Журнал действий: `actions.jsonl` там же. Метки ранних проб не гарантируют
  ожидаемое состояние: native picker может оставаться открытым; `Esc` иногда
  возвращает в библиотеку вместо закрытия popup. Достоверные состояния ниже
  проверены по фактическому дереву/изображению, а не только по имени снимка.
- Изменяющие файлы команды выполнялись на трёх специально сгенерированных JPEG:
  1200×800, 800×1200, 500×500. Проверены поворот, избранное и подтверждённое
  удаление одного такого файла; личные оригиналы не изменялись.
- Создан, переименован и удалён только временный тестовый альбом. Исходный альбом
  не менялся. Временный источник удалён через Settings; тестовый каталог удалён.
- Восстановлены: единственный исходный источник, wheel=next/previous,
  linked duplicates=On, theme=System, Tile=Recent photos, auto albums=On,
  album notifications=On, крупная плотность, показ верхних карточек,
  Collection, maximized. Облачные/лицевые/видео-переключатели не трогались.
- Помощник и временные scheduled tasks остановлены и удалены, отсутствие проверено.
- **Не все кнопки всех веток проверены.** Не включались cloud/People/preview,
  не отправлялись feedback/share, не выполнялись реальная печать или смена обоев.
  Редактор обследован по основным страницам, без перебора каждого фильтра/слайдера:
  редактирование по требованиям отложено. Системные Minimize/Close не проверялись
  как отдельные сценарии. Ниже это не следует считать покрытием.
- Сенсорная инъекция через Windows Touch Injection отклонена (`ERROR_INVALID_PARAMETER`,
  первый кадр). **Реальные pinch/swipe/инерция и длительное касание не подтверждены**.
  Мышиная автоматизация их не заменяет.

## 1. Система координат и визуальная иерархия

Все размеры далее — логические единицы (физические координаты UIA / 2).
Maximized client: **1500×960**; taskbar вне client, 40.

| Область | Размер / положение |
| --- | --- |
| Title bar | y=0…32 |
| Back в дочернем экране | x=0…48, y=0…32; не в command bar |
| Название без Back | x=12, y≈8; высота текста 16 |
| Название с Back | x=60, y≈8 |
| Minimize / maximize / close | каждая примерно 46×32 справа |
| Command bar | y=32…80, высота 48 |
| Library tabs | y=80…128, высота 48 |
| Поиск большой библиотеки | x=120, y=38, 396×36 |
| Поле контента библиотеки | x≈120…1380, ширина≈1260 |
| Настройки | отдельная страница; не маленькое плавающее окно |

Основные элементы плоские, прямоугольные, без обычного egui button frame.
Обычный текст библиотеки около 14, команды около 12–14, title bar 12–16;
точное соответствие шрифта/метрик ещё нужно откалибровать, это визуальные оценки.
Большое название альбома лёгкое, около 46; заголовки Settings около 24–32.
Синий акцент близок к #0078d7, выбранная вкладка с короткой нижней линией.

### Backdrop

Библиотека: title + commands используют один behind-window acrylic backdrop
с tint/noise. Tabs и содержимое непрозрачны. Viewer: acrylic только title,
commands белые. При потере фокуса acrylic становится непрозрачным серым.
Это уже подтверждено сравнением active/inactive, не следует имитировать
постоянным градиентом. Временный непрозрачный fallback допустим только как
явно обозначенный недостающий эффект, не как завершённая реализация.

## 2. Коллекция

### Обычный режим

- Search слева, команды справа. В референсе есть video/import/account; их
  исключение в Rphotos не оправдывает перенос поиска или изменение высоты шапки.
- Collection / Albums / Video projects / People / Folders. В Rphotos остаются
  Collection / Albums / Folders с сохранением общего стиля/ритма.
- Справа на строке вкладок три маленьких **графических** переключателя плотности,
  не текстовые L/M/S. Область каждого около 25×44; выделение нижней синей чертой.
- Верхние discovery cards — горизонтальный ряд с обложкой и текстовым подвалом,
  слабой тенью, крестиком при наведении. Пример большой карточки ≈243×162.
  Видимые кнопки View, Hide this tile; Hide all tiles справа под рядом.
- Проверен Hide all / Show all; скрытие **отдельной** карточки не проверено,
  чтобы не менять пользовательские рекомендации необратимо.
- Hide убирает карточки, оставляя строку Show; начало списка сдвигается вверх
  с y≈332 до y≈158. Это не просто сворачивание фиксированной пустой области.
- На сетке нет постоянных подписей имён файлов под каждым изображением.
  Filename виден в tooltip; выбранный снимок получает рамку и галочку.

### Размеры сетки — не одинаковые карточки

Фактические измерения одного и того же изображения 3:2 на большом окне:

| Плотность | Ширина×высота одного примера | Промежутки |
| --- | --- | --- |
| Large | 768×512 | около 12 между соседями |
| Medium | 384×256 | около 12 между соседями |
| Small | 144×96 | около 6 между соседями |

Другие пропорции дают другую ширину. Заполненная строка может перераспределять
ширины/обрезать изображение: например synthetic square и portrait в одной
Large-строке получили ≈737 и 511 при высоте 512. **Не выводить алгоритм только
из этих трёх чисел.** Нужна воспроизводимая aspect-aware раскладка, проверенная
на разных последовательностях и остаточной строке. Текущая сетка Rphotos из
равных fit-клеток с filename footer этой композиции не соответствует.

### Даты и навигация

- Синий месяц+год — первая строка, примерно 30 по высоте.
- Под ним серый день или диапазон дат + число снимков. При выделении вместо
  количества — Select / Select all N / Unselect для группы.
- Группы могут объединять несколько дней, это **не обязательный заголовок
  перед каждым календарным днём**, как в текущей реализации.
- Нажатие на месяц действительно включает **semantic zoom**: изображения
  заменяются вертикальным списком месяцев с шагом около 48.
- В этом режиме часть верхних команд неактивна, Back появляется в title bar.
- Выбор месяца возвращает сетку и переводит к нужной группе.
- Справа timeline: тонкая линия, точки месяцев, подписи годов и круглый текущий
  ползунок. Это отдельная календарная навигация, не обычный scrollbar в контенте.
  Нажатие исследовано; drag scrubber и точная привязка к позиции ещё не измерены.
- Правое меню миниатюры: Delete, Share, Copy, Print, Favorites; Add to,
  Change date; Slideshow; Open in File Explorer, Open in folders, с разделителями.

### Поиск

- Фокус пустого поиска раскрывает panel **той же ширины**, поверх содержимого.
  Внутри заголовки THINGS, HIGHLIGHTED; строки примеров около 32.
- В этом сеансе примеры: Screencap, Smile, Grin; Text. Они зависят от индекса,
  не должны быть захардкожены как фиктивные результаты.
- Screencap проверен: поле заполнено, карточки скрыты, сетка показывает
  отфильтрованные группы. Поиск — не только filename.
- Полный OCR/semantic pipeline Rphotos ещё отсутствует; визуальный dropdown
  сам по себе не считается реализованным содержательным поиском.

## 3. Выделение и модальные состояния

- Select заменяет **command bar**, а не добавляет ещё одну полоску.
- Фон charcoal, светлые символы; title bar остаётся acrylic.
- Слева No item selected / N items selected на x≈120.
- Справа Add to, Share, Print, Copy, Delete, Cancel, overflow; video исключается.
- Discovery cards скрыты; видимая строка вкладок оставляет текущую Collection.
- Выбор изображения **не открывает viewer**, синий контур толщиной около 4,
  квадрат с галочкой вверху справа. У невыбранных показывается пустой квадрат.
- Cancel возвращает обычные команды и разделы.
- Add to — центрированная панель **360×648**, тонкая акцентная рамка,
  светлый фон, осветлённое/заблокированное содержимое снаружи. В ней заголовок,
  количество, New album, существующие альбомы с миниобложкой. Video исключается.
- New album **внутри этой панели** заменяет верхнюю часть на поле имени,
  Create album + Cancel; существующие альбомы ниже остаются видимыми.
- После создания/добавления есть notification strip под commands с текстом,
  View album и Close; она временно сдвигает вкладки вниз примерно на 44.
- Delete вызывает компактный центрированный confirmation: заголовок,
  Delete / Cancel. Отмена проверена на личной миниатюре; подтверждение — только
  на generated JPEG. После подтверждения viewer перешёл к соседнему снимку.

## 4. Альбомы

### Список

- Общая шапка библиотеки. Справа вместо density — Sort by.
- Варианты: **Modified / Newest / Oldest / Alphabetical** (popup обследован;
  все четыре порядка не проверялись на большой коллекции).
- Ниже раскрываемая секция Albums (N), затем плитки.
- В большом окне tile≈303×198, шаг по горизонтали315; 4 колонки в ширине1260.
- Первая плитка синяя New album с плюсом и пояснением. Остальные — обложка,
  имя и N items. Не вертикальный список стандартных кнопок.

### Открытый альбом

- Back в title; commands Slideshow / Add photos / Share / Select / overflow.
- Название крупное, центрированное, редактируемое; рядом pencil.
- Вход в изменение имени заменяет команды на **Done / Cancel / overflow**.
  `Esc` в наблюдавшемся сеансе не вышел из этого режима — нужен Cancel.
- Обложка x≈144, y≈205, **1212×426** на окне1500×960, ниже дата/диапазон
  слева и density справа, затем aspect-aware фотографии.
- Preview обложки может автоматически проигрывать slideshow/анимированное
  представление, появляются Pause preview / Watch / Edit. Видео-создание
  исключено из Rphotos; не следует незаметно подменять его нерабочими кнопками.
- Overflow: Remove, feedback. Remove confirmation явно сообщает, что файлы
  внутри **не удалятся**. Создание, rename Done и Remove подтверждены на тестовом
  альбоме; исходный альбом только открыт, rename отменён.

### Создать / добавить фотографии

- New album в списке **не сразу поле имени**: отдельный полноразмерный picker.
- Header: Create new album + пояснение; справа Create / Cancel.
- Внутри встроены поиск, Collection/Folders, density и выделяемые фото.
- Add photos в существующем альбоме открывает тот же picker с заголовком
  Add to <album>, кнопкой Add. Оба сценария открыты и отменены без изменений.
- Название нового тестового альбома задано через Add-to panel в viewer;
  завершение отдельного full-page picker ещё не проверялось.

## 6. Просмотрщик — точная композиция

### Command bar

- **Никакого Back внутри command bar и никакого постоянного счётчика справа.**
- Слева Add to. В центре пять кнопок: Zoom / Delete / Favorite / Rotate / Crop.
- На окне1500 центр-кластер: x≈626.5…874, каждая≈49.5×48.
- Справа Edit & Create (≈139×48), Share (≈82×48), Print (48×48), overflow(48×48).
- File info находится в overflow, **не в центре вместо Favorite/Rotate/Crop**.
- Редактор отложен; архитектурно предусмотреть позиции/компоновку, не выдавать
  незавершённые операции за рабочие. Compare — дополнительная функция Rphotos,
  ей место в overflow, не вместо референсных команд.

### Изображение и боковые зоны

- Viewer content начинается y=80. В UIA фон изображения имеет rect
  x=32, y=80, width1436, height848 (до y=928). Это **не inset32 со всех сторон**:
  сверху нет дополнительных32, снизу есть32.
- Synthetic1200×800 при Fit на окне1500×960 занимал x=150…1350,
  y≈104…904. Actual size занимал 600×400 логических единиц при200% DPI,
  т.е. один исходный пиксель = один физический пиксель экрана.
- После открытия info область изображения действительно сужается, fit пересчитан.
- Previous/Next: невидимая hit-зона шириной100 у края, y≈128…879.
  Большой тонкий chevron по центру, не маленькая framed button в постоянной полосе.
  На границе отсутствует соответствующее направление; проверены переходы.
- Fullscreen: 48×48, x=1440,y=904, отступ справа/снизу12/8.
- Нет filmstrip, footer и постоянного navigation slider.
- Fullscreen убирает title/commands/taskbar; одно изображение на белом фоне,
  выход внизу справа. Slideshow также полноэкранный, **не тот же интерфейс с
  четырёхсекундным таймером при видимой шапке**. Старт/выход проверены; точный
  интервал, порядок/loop и все slideshow controls ещё не установлены.

### Zoom popup

- Локальная светло-серая flyout поверх фото, привязана к Zoom; viewport не движется.
- UIA slider rect≈x561.5,y86,width180,height44. Внешняя panel шире slider,
  по снимку около244; точный outer rect требует отдельного измерения.
- Range0…100, small1, large10. 0 сообщает Best fit,100 — Maximum zoom.
- Это **позиция референсного slider, не непосредственно процент масштаба**.
  Значения25/100/0 проверены, но формула соответствия масштабу не установлена.
  Нельзя считать их 25%/100% или произвольно заменить logarithmic0.1…20.
- Overflow переключает View actual size ↔ Zoom to fit. 100% должен учитывать DPI.
- Mouse wheel=next/previous подтверждён раньше; Ctrl+wheel всегда zoom согласно
  настройкам. Точность кривой, doubleclick и сброс pan требуют отдельной проверки.

### Info panel

- Левая **344** шириной, фон≈#f2f2f2, начинается сразу под commands (y80).
- Title File info на x24,y≈98; Close48×48 справа.
- Контент x24…320 (ширина296), scroll отдельно от фото.
- File name: подпись+input без extension. Date taken: два boxed picker,
  даты и времени; popup с wheel-колонками и Confirm/Cancel.
- Затем Size, Dimensions, Shot, ISO, Device, Folder path, Open folder, Source.
- Ритм обычных полей: label y324/value344, следующий label384/value404,
  т.е. около60 на простое поле. Нет данных на скриншоте выглядит как `--`.
- Для Rphotos пока read-only по прежнему решению об отложенном редактировании;
  визуально сохранить структуру и явно не обещать запись метаданных.

### Меню и подтверждения

Overflow большой ширины: Slideshow, Save as, Resize, Copy; Open with, Set as;
View actual size/Zoom to fit; File info; feedback; Settings. Обычная строка32
высотой, popup≈158 шириной; группы разделены дополнительными промежутками.

- Save as открывает native picker; проверено открытие и Cancel, без сохранения.
- Resize открывает отдельный centered dialog: текущие MP, Small0.25MP,
  Medium2MP, Large4MP, Custom. Custom: Width/Height, Maintain aspect ratio,
  Quality10…100 (default80), Save resized copy. Изменены только поля диалога,
  выход без записи. Это будущий editor/export scope, не обязательство делать сейчас.
- Set as раскрывает submenu слева: lock screen / background / app tile.
  Ничего из этого не применялось.
- Open with вызван, но chooser **не появился**; системная интеграция не подтверждена.
- Share вызван, но видимая flyout снова не появилась. Наличие самого пункта
  проверено, работа платформенной отправки — нет.
- Context menu фотографии содержит также Open folder; изучено, без запуска
  внешних приложений. Copy не вызывался, чтобы не затирать пользовательский clipboard.

## 7. Узкое окно

Проверен outer1120×1440 физических, client≈547×713 логических.

- Height строк не меняется; commands остаются одной строкой, **не wrap**.
- Viewer сохраняет Add to слева, пять центральных icons; Edit/Create становится
  значком с маленьким chevron. Share/Print переходят в **начало overflow**.
- Overflow ограничен по высоте, последние действия требуют прокрутки.
- Библиотечный поиск сжимается примерно до224 ширины, часть команд уходит.
- Tabs прокручиваются/обрезаются; discovery cards — горизонтальная карусель
  с отдельными боковыми стрелками, а не перенос вниз.
- Изображение сохраняет пропорции с большими свободными полями, fullscreen справа снизу.
- Длинные RU labels, минимальная ширина и портретная ориентация **всего экрана**
  ещё не прошли отдельную систематическую матрицу.

## 8. Settings и печать

Settings: Back в title, крупный heading в верхней области. Содержимое отдельным
scroll, x24, максимальная ширина текстовой колонки≈532; справа пустое место.
Разделы с большими вертикальными промежутками. Это не набор compact ComboBox.

Проверено изменение и восстановление:

- Linked duplicates On→Off→On.
- Mouse wheel next/previous→zoom→next/previous.
- Mode System→Dark→Light→System. UI сообщает **изменение после перезапуска**;

## 9. Приоритет исправлений Rphotos

Это backlog, а не выполненные изменения:

1. Общая custom title32 + commands48: правильный Back/title, platform window
   controls, acrylic/focus fallback. Не подменять отдельным OS title + Back toolbar.
2. Собрать измеренный viewer: центр-кластер, right commands, **zoom flyout**,
   info344, правильный image viewport, невидимые edge zones, narrow overflow.
3. Библиотечная шапка с search/commands/tabs/density без переноса строк;
   selection заменяет commands; простые маленькие icons, точная типографика.
4. Aspect-aware gallery без filename footer, месяцы/диапазоны, group selection,
   timeline и semantic zoom. Сохранить виртуализацию и background decode.
5. Albums/Folders как tile-scenes, album detail/cover/rename и отдельный picker,
   folders с вложенными каталогами; не маскировать фильтрацию под эти экраны.
6. Полноэкранная Settings и корректные popup/modal/notification transitions.
7. Подтвердить настоящие touch gestures, theme restart и сложные узкие состояния.
8. OCR/semantic search, auto albums и platform print/share остаются отдельной
   функциональной работой. Редактор, cloud, People, import и video не расширять.

### Критерий приёмки следующего визуального прохода

Одинаковые synthetic изображения, одинаковый logical viewport/DPI,
детерминированный выбранный экран. Сначала сравнение silhouette/layout и
координат, затем шрифтов/icons/states. Отдельные capture для normal/hover/focus,
popup/modal, narrow и info. Offscreen screenshot без custom title не доказывает
сходство всего окна; build/tests не доказывают визуальную точность. Нельзя
называть следующий проход «максимально похожим» без такой сверки.
